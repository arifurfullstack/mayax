# PART 2: UI/UX & Architectural Issue Analysis & Action Plan

## 1. Logout Failure & Stuck Loading Screen on Refresh

### Root Causes
1. **Uncaught Promise Deadlock in `useAuth`:**
   In `src/hooks/useAuth.tsx`, `applySession()` invokes `await loadUserData(user.id)`. If any profile lookup or role query fails or takes long, `setLoading(false)` is never called because there is no `try...finally` block.
2. **Infinite Guard Blocking in `AuthGuards.tsx`:**
   `AuthGuards.tsx` renders a permanent `<LoadingScreen />` whenever `loading === true`, without any timeout or fallback mechanism.
3. **`signOut()` Doesn't Force Clear Local State:**
   `signOut()` awaits `supabase.auth.signOut()`. If the remote network request to GoTrue hangs, the local user state is never cleared, forcing users to manually flush `localStorage`.

### Recommended Solution
1. **Wrap `applySession` in a `try...finally` block:**
   ```ts
   const applySession = async (session: Session | null) => {
     try {
       setSession(session);
       setUser(session?.user ?? null);
       if (session?.user) {
         await loadUserData(session.user.id);
       } else {
         resetUserState();
       }
     } catch (err) {
       console.error("Auth initialization error:", err);
     } finally {
       if (alive) setLoading(false);
     }
   };
   ```
2. **Add a Fail-Safe Auth Timeout:**
   Set a 3.5s timeout on mount. If Supabase does not resolve the session within 3.5 seconds, set `loading = false` to prevent the app from freezing.
3. **Bulletproof `signOut` Execution:**
   ```ts
   const signOut = async () => {
     try {
       await Promise.race([
         supabase.auth.signOut(),
         new Promise((res) => setTimeout(res, 1200)) // 1.2s timeout fallback
       ]);
     } catch (e) {
       console.warn("SignOut API error:", e);
     } finally {
       localStorage.clear();
       sessionStorage.clear();
       resetUserState();
       window.location.href = '/login'; // Hard redirect clears in-memory state
     }
   };
   ```

## 2. Page Unresponsiveness & Lack of Server-Side Pagination

### Root Causes
- In pages like `AdminLeads.tsx` and `Marketplace.tsx`, the application queries all **3,682 leads** in a single unconstrained query (`.select('*')`).
- Rendering 3,600+ complex table rows or card components simultaneously causes severe memory bloat and locks the main JavaScript thread.

### Recommended Solution
Implement PostgREST range-based pagination with exact counts:

```ts
const PAGE_SIZE = 25;

const fetchLeads = async (page = 1, searchQuery = '', statusFilter = 'all') => {
  const from = (page - 1) * PAGE_SIZE;
  const to = from + PAGE_SIZE - 1;

  let query = supabase
    .from('leads')
    .select('id, reference_code, full_name, price, quality_grade, ai_score, review_status, sold_status, created_at', { count: 'exact' })
    .order('created_at', { ascending: false })
    .range(from, to);

  if (searchQuery) {
    query = query.or(`reference_code.ilike.%${searchQuery}%,full_name.ilike.%${searchQuery}%`);
  }
  if (statusFilter !== 'all') {
    query = query.eq('sold_status', statusFilter);
  }

  const { data, count, error } = await query;
  return { data, total: count || 0, totalPages: Math.ceil((count || 0) / PAGE_SIZE) };
};
```
- Fetching 25 items takes **~30ms** instead of freezing the browser.
- Add a shared `<Pagination />` component with "Previous", "Next", and direct page buttons.

## 3. Dark Mode Table Theming Issues

### Root Causes
- Table elements (`<Table>`, `<TableHeader>`, `<TableRow>`, `<TableCell>`) or their parent wrappers rely on hardcoded light utilities (`bg-white`, `border-gray-200`, `text-gray-900`) instead of semantic Tailwind theme tokens.
- When toggling to dark mode, the container switches to dark while the inner table remains bright white.

### Recommended Solution
1. Standardize `src/components/ui/table.tsx`:
   - Table background: `bg-transparent` (inherits from container).
   - Table header: `bg-muted/40 text-muted-foreground border-b border-border`.
   - Table rows: `border-b border-border hover:bg-muted/50 data-[state=selected]:bg-muted`.
   - Table cells: `text-foreground`.
2. Wrap tables in standard card containers:
   ```tsx
   <div className="rounded-xl border border-border bg-card text-card-foreground shadow-sm overflow-hidden">
     <Table>...</Table>
   </div>
   ```

## 4. Mobile Responsiveness Failures

### Root Causes
1. **Fixed Sidebar Layout:** `AdminLayout.tsx` renders a fixed `w-64` desktop sidebar without a mobile collapsible drawer. On screens < 768px, it occupies 70%+ of the viewport.
2. **Table Container Overflow:** Tables with 8 to 10 columns lack an `overflow-x-auto` wrapper, forcing the entire page body to stretch horizontally and breaking page alignment.
3. **Rigid Grid Breakpoints:** Dashboard metric cards use fixed columns (`grid-cols-4`) without responsive fallbacks (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`).

### Recommended Solution
1. **Add Mobile Sheet Navigation:**
   In `AdminLayout` and `ProviderLayout`, render a top app bar on mobile (`md:hidden`) with a hamburger icon triggering a Shadcn `<Sheet>` drawer containing the navigation links.
2. **Wrap All Tables:**
   Wrap every table instance in:
   ```tsx
   <div className="w-full overflow-x-auto rounded-lg border border-border">
     <Table className="min-w-[700px]">...</Table>
   </div>
   ```
3. **Normalize Container Padding:**
   Change page root wrappers from `p-8` to `p-4 sm:p-6 lg:p-8`.
